## Evidence, reproduction, and root cause

- The user's v5.0.5 screenshot shows `0 canvases` and `2 inline canvas previews could not yet be captured`, while both widgets render. The Tampermonkey Beta screenshot shows v5.0.5 enabled with Google, HTTPS shim, and blob include patterns; it does not prove that the script actually executed within the nested frame.
- The new Desktop `(2).html` contains two inline `iframe.lQ27pc` candidates, but no authored source in its parent DOM. The new `(2).har` has 187 requests. Four sandbox shim responses are present; their 7,245-character script accepts a `message` with `body` and `mimeType`, validates a checksum, constructs a Blob, and calls `location.replace(blobURL)`. The HAR does not capture the blob payload itself. The `(2).md` records three conversation segments and zero canvases.
- Read-only Chrome inspection confirms the first outer blob holds a child blob whose rendered document contains an authored ~22 KB module, ~20 KB CSS, and `#root`. v5.0.5's challenge/reply path depends on the userscript executing in that *later* blob document. Chrome does not guarantee content-script injection into blob frames from a userscript `@include` regex; it requires extension-level related-frame matching. Tampermonkey's default Content Script API also does not guarantee true `document-start` execution. These are plausible causes of the missing reply, not proven injection-state facts.
- Even if the HTTPS shim supplies the original source, v5.0.5's validator rejects a React page whose initial `#root` is empty because it requires 30 characters of body text. Its reused side-Canvas HTML builder has the same body-text gate. Both must be relaxed *only* for a complete inline HTML document with a substantive authored module.

## Target behavior and implementation

1. In the HTTPS shim branch, listen for the trusted parent message carrying `text/html` and a bounded complete authored module document. Before the shim navigates to blob, send that document directly to `https://www.google.com` via tab-local `postMessage`. Ignore non-HTML, oversized, incomplete, or untrusted-parent messages. Do not add grants, source uploads, external persistence, or Google security bypasses.
2. Install the Google top-page message listener at userscript execution time, not DOMContentLoaded. Accept an unsolicited preload only if its origin is HTTPS `*.scf.usercontent.goog`, its `event.source` matches the live outer or indexed nested WindowProxy of a current `.MngkG iframe.lQ27pc`, and the full HTML validates. Also bind a reply to the 192-bit nonce sent only to that frame if an extension world reports `event.source === null`. Reject off-route, stale, spoofed, and detached sources. Retain the v5.0.5 blob challenge fallback.
3. Permit initially empty React mount markup for the inline format when a substantive `script[type=module]` exists. Keep the existing side-Canvas reconstruction path unchanged. Reuse the established inline sanitizer and route-scoped registry. Update the panel warning to identify the nested HTTPS shim permission rather than implying blob injection is mandatory.
4. Bump to v5.0.6 and update README, changelog, browser matrix, and tests. Preserve the original v5.0.5 failure record and prior evidence files.
